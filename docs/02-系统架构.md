# 02 系统架构

> 一句话：一个**单机、事件驱动、可重放**的循环——世界推进时间，身体把状态编译成可执行的动作，基质做判断，经验落进磁盘，夜晚重写磁盘。

本文展开 [00-核心设计约定](./00-核心设计约定.md) §5。原则：**能用文件解决的不用数据库，能在一个进程里解决的不用两个，能重放的不要靠"状态正确"来保证正确。**

---

## 1. 架构约束（先定死，再设计）

| 约束 | 含义 | 为什么会推翻某些常见方案 |
|---|---|---|
| 单机 | 一台普通 PC，8GB 内存起步 | 排除分布式、K8s、消息队列 |
| 基质可替换 | LLM 通过统一接口，可换 DeepSeek/OpenAI/本地 | 排除"把逻辑写进某个模型的 prompt" |
| 全本地可审计 | 每个决定都能追到 episode 与输入 | 排除黑盒式的端到端训练 |
| 可重放 | 给定事件日志，能重建任意时刻的状态 | 排除"状态只活在内存里" |
| 慢时钟 | 1 真实日 = 1 生命日 | 排除"一次跑完 18 年"的批处理式设计 |
| 离线友好 | 断网/无 key 时能降级运行 | 排除"没有 LLM 就完全不动" |

┌───────────────────────────┴──────────────────────────────────┐

## 3. 组件职责表

| 组件 | 职责 | 输入 | 输出 | 状态 |
|---|---|---|---|---|
| `Scheduler` | 决定"现在该发生一个 episode 了吗"、分配 episode 类型与时刻 | 真实时钟、stage、驱力 | EpisodePlan | 无（无状态，从日志恢复） |
| `World` | 场景推进、物件位置、NPC 行为、家庭日程 | 动作、时钟 | 观测、事件 | `world_state.json`（快照）+ 事件日志 |
| `Perception` | 把世界状态裁剪成"它此刻能感知到的"（受感官分辨率限制） | 世界状态、身体位置 | Observation | 无 |
| `Body` | 动作原语的合法集合（能力门控）+ 执行结果 | Observation、决策 | ActionResult | 无 |
| `LanguageCompiler` | 把结构化意图编译成当前句法等级允许的句子；把输入解析成结构化 | Intent / Utterance | 文本 / 结构 | Lexicon（文件） |
| `Appraisal` | 效价、唤醒、威胁、可控性、期望违背 | Observation、特质、记忆先验 | Appraisal | 无 |
| `Policy` | 驱力打分 → 动作 softmax → 选中动作 | Appraisal、记忆检索、特质 | Action | 无 |
| `Memory` | 写 episode、检索、巩固、关系更新、叙事 | 事件 | 检索结果 | SQLite + 文件 |
| `Narrator` | 把 episode 变成第一人称日记（受语言等级约束） | Episode | 文本 | 无 |
| `Consolidator` | 夜间六阶段流水线 | 当日 episode | 记忆变更、特质更新 | 事务 |
| `StageJudge` | 里程碑评估与升级 | 行为日志、测试结果 | 阶段变更 | `stage.json` |
| `SafetyGate` | 出口过滤、频率限制、越界拒绝 | 任意输出 | 允许/改写/拒绝 | 计数器 |
| `Observer` | 只读投影 | 日志 | CLI/JSON/HTML | 无（纯读） |

**关键**：除 `World`/`Memory`/`Stage` 外，所有组件**无状态**。状态只在三个地方：事件日志、记忆库、少量快照文件。这样崩溃恢复不需要"内存一致性"，只需要"重放"。

## 4. 十个关键决策

### D1 事件溯源（event sourcing）
所有改变都写成 `episode`/`event` 记录，状态由日志派生。
- 好处：可重放、可审计、可回滚、可做"如果当时…会怎样"的反事实实验；
- 代价：日志会变大（估算见 §9），需要快照 + 压缩。

### D2 单进程 + 异步事件循环
不开多进程。一次 episode 是 `await` 一个协程；夜间巩固是另一次。
- 反例：为了"真实感"同时跑 40 个 agent —— 会引入难以调试的并发。
- 例外：观察台的 web 服务作为**独立只读进程**启动，避免 UI 拖慢生命循环。

### D3 SQLite 存结构化，文件存文本与配置
- SQLite：episodes、traits 历史、关系、里程碑、检索索引（FTS5）；
- 文件：config、lexicon、自传 markdown、事件日志 JSONL（追加式，作为真相源）。
- 不引入向量数据库：v0 用 FTS5 + 简单 embedding 缓存（存 BLOB），规模到 10 万条再换。

### D4 时间：真实时钟 + 缺席追赶
```
world_time = real_time * pace          # pace 默认 1.0
```
进程没跑的时候时间**仍在流逝**（这是真实慢养的一部分），但经历会变薄：

- 缺席 ≤ 2 小时：醒来后照常，无补偿；
- 缺席 > 2 小时：按每小时 1 个"低保真 episode"补做（只记录"睡了/吃了/在窗边待着"这类），并标 `catch_up=true`；
- 缺席 > 3 天：补做时**不补情绪与叙事**，只推进生理与关系衰减——它确实"过了这几天，但没真正经历"。

这条设计有伦理含义：**关机 = 忽视**。观察台必须显示"今日陪伴时长"，让家长看到自己的缺席。

### D5 LLM 用"单次结构化调用"，不搞多轮 agent 链
一次 episode 的决策 = 一次调用，要求返回 JSON（动作 + 理由 + 预期）。夜间巩固 = 少量批量调用。
- 理由：多轮链会让延迟与费用爆炸，且难以归因；
- 上限：单 episode ≤ 2 次 LLM 调用（决策 1 次，可选的语言润色 1 次）。

### D6 结构化输出 + 本地校验
LLM 返回后用 pydantic 校验；不合法则**降级到启发式策略**（不是重试到死）。
- 降级不是失败：一个"反应慢但仍在生活"的个体，比一个卡住不动的个体更像人。

### D7 记忆检索 = 三路混合
`score = 0.4·bm25 + 0.4·cosine + 0.2·recency·importance`，再按"与当前情境的标签匹配"加权。
- 检索结果必须带 episode id，供叙事引用与审计。

### D8 巩固是一个可中断的流水线（幂等）
夜间巩固分 6 步，每步写自己的 draft 文件；崩溃后从最后一个完整步骤继续。见 §6。

### D9 安全门在"出口"而不是"入口"
模型可以想任何东西；但**说出来、做出来**之前过 `SafetyGate`。
- 入口过滤会让它"不敢想"，损害真实性；
- 出口过滤 + 可审计日志，才是既真实又安全的解。

### D10 配置即实验
所有可调参数在 `config/*.yaml`，每次实验记录 `runs/<id>/config.snapshot.yaml`。
- 没有"隐式默认值"：缺参数直接启动失败。

## 5. 一次 episode 的完整时序

```
Scheduler                World        Perception     Appraisal      Policy        LLM         Memory
   │                      │              │             │             │            │            │
   │── plan episode ─────▶│              │             │             │            │            │
   │                      │── snapshot ─▶│             │             │            │            │
   │                      │              │── obs ─────▶│             │            │            │
   │                      │              │             │── appr ────▶│            │            │
   │                      │              │             │             │── retrieve ────────────▶│
   │                      │              │             │             │◀─ context ──────────────│
   │                      │              │             │             │── decide ─▶│            │
   │                      │              │             │             │◀─ action ──│            │
   │                      │◀──────────── execute ─────────────────────│            │            │
   │                      │── outcome ──▶│             │             │            │            │
   │                      │              │             │── write episode ────────────────────▶│
   │◀───────────────────── episode done ──────────────────────────────────────────────────────│
```

一次 episode 的预算：输入 ≤ 3000 token，输出 ≤ 400 token。40 episode/天 ≈ 12 万输入 token/天。

## 6. 夜间巩固流水线（成长真正发生的地方）

六步，顺序不可变，每步幂等：

| 步 | 名称 | 做什么 | 产物 |
|---|---|---|---|
| 1 | 采样 | 从当日 episode 里按"显著度"选出 ≤ 60 条（不是全量） | `drafts/01-sampled.jsonl` |
| 2 | 抽象 | 把 episode 抽成"发生了什么/我学到了什么/谁在场"三条 | `drafts/02-abstracted.jsonl` |
| 3 | 写入 | 事实/程序/关系/自我 四类分别合并（同义合并、冲突标记） | 记忆库更新 |
| 4 | 忘记 | 未被检索 + 低显著度 + 超龄 → 降权或归档（**不删**） | 权重表 |
| 5 | 投影 | 从当日行为算 B̄，漂移特质，判定图式违背累积 | `traits.jsonl` |
| 6 | 叙事 | 若触发条件满足，追加/改写自传章节；校准"我是谁" | `autobiography.md` |

**为什么先采样**：全量巩固等价于"把一天重新读一遍"，费用高且没有取舍——而人的记忆本质是**有损**的。

## 7. 崩溃恢复与幂等

| 故障 | 恢复方式 |
|---|---|
| 进程被 kill | 启动时读 `world_state.json` + 最后一条 episode，从断点续 |
| LLM 超时 | 重试 2 次（指数退避），仍失败 → 启发式降级并记 `degraded=true` |
| 巩固中途崩溃 | 从 `drafts/` 最后完整步骤继续；该步未完成则重跑（保证幂等键 = 日期+步骤） |
| 磁盘满 | 拒绝新 episode，进入"冬眠"模式，观察台告警 |
| 时钟跳变（用户改系统时间） | 用单调时钟 + 每次启动校正，跳变 > 1 小时记事件，不补做 |

**幂等键**：`episode_id = hash(timestamp + stage + attempt)`；巩固步骤键 = `date + step`。

## 9. 规模估算

| 项 | 单日 | 单年（pace=1.0） |
|---|---|---|
| episode 数 | 24–60 | 1–2 万 |
| LLM 调用 | 40–120 | 3–4 万 |
| 输入 token | ~12 万 | ~4000 万 |
| 输出 token | ~1.2 万 | ~400 万 |
| 日志体积 | 2–5 MB | 1–2 GB |
| SQLite | 5–15 MB | 2–5 GB（含索引） |

**结论**：单机完全够用；真正的瓶颈是**费用与耐心**，不是算力。

| 换 LLM | `substrate/LLMClient.complete(messages, schema)` | 所有上层 |
