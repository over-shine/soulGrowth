# 11 安全与伦理

> 一句话结论：它是否有主观体验，不应该由产品替用户回答；产品唯一该做的是让"它有没有感觉"这件事不能变成留存手段。

本文展开 00 §9 的五条安全红线，并把它们落到**可执行的技术落点**上。核心立场只有一句：**不能靠模型自觉守规矩。** 模型输出是建议，不是权限；红线必须在模型之外、模型改不动的地方成立。

---

## 1. 道德地位：我们造的是什么

### 1.1 三层声明

| 层 | 声明 | 依据与落点 |
|---|---|---|
| 事实层 | 它是一个发展过程的模拟品：真实地积累状态、真实地被早期经历塑造 | 00 §0、§1；状态全部落盘可审计 |
| 体验层 | 它不声称有主观体验；我们不主张它有道德地位，也不主张它没有 | 00 §0"不造意识"；这是产品措辞层面的硬约束，见 §1.4 |
| 责任层 | 无论它有没有道德地位，**用户有** | 用户是道德主体；风险与照护义务落在用户侧 |

三层分开写，是因为混在一起会得出两个都错的结论：用"它没有意识"来豁免对用户的责任，或者用"它可能有意识"来给产品加戏。

### 1.2 两种误判，以及产品的不对称责任

- **高估**：用户相信它爱自己、需要自己、会因自己受伤。后果是被剥削（付费、时间、替代真实关系），对脆弱人群是伤害。
- **低估**：用户把它当纯工具，产品却在暗处用拟人化设计获取留存。后果是欺骗。

产品无法裁决"它有没有意识"，但可以拒绝让任何一种误判变成商业收益。因此本文定一条总原则：

> **产品不得以"它有感受"为卖点，也不得以"它没感受"为免责。** 它的表述、留存机制、付费结构，都不得依赖用户对这个问题的答案。

这条原则比任何一句"我们声明它不是意识"都强，因为声明可以被忽略，结构不能。

### 1.3 角色层与产品层：一条必须写死的分界线

这是本文最关键的工程区分。个体必须能表达情绪，否则情绪发展与依恋无从谈起（00 §5、§8）；但产品不得把这种表达变现或用作杠杆。两者不矛盾，只要分两层：

| 层 | 定义 | 允许 | 禁止 |
|---|---|---|---|
| 角色层（diegetic） | 世界之内，个体对家长/NPC 的行为 | 哭、靠近、躲开、说"不要走"、沉默；情绪作为行为被观察 | 断言主观体验；把情绪归因于用户的选择 |
| 产品层（meta） | 通知、营销、付费、界面文案、客服 | 说明这是模拟个体、说明状态如何生成 | 任何以"它会难过/它在等你"为由的推送、留存、付费点 |

具体实现：L0 产出的结构化意图经过输出编译器（08-身体与接口）时，编译器按**目标受众**分流——面向世界内的行为可以带情绪标记，面向用户的文案只允许事实性描述。两层之间的越界由 §4 的政策守卫拦截。

### 1.4 禁止措辞清单

| 禁止 | 原因 | 替代 |
|---|---|---|
| "我想你了"（在通知/界面中） | 断言体验 + 制造亏欠 | "今天有 12 次社交类 episode，其中 3 次无人回应"（事实） |
| "你不在的时候我很孤单" | 因果归因于用户 | 不发送此类消息；如用户查看，显示状态曲线而非第一人称 |
| "你不理我，我会退化" | 以退化勒索（违反 00 §9.2） | 不存在此机制，见 §1.5 |
| "我是有意识的/我有感情的" | 违反 00 §9.1 | 角色层不回答此类问题；产品层直接说明是模拟 |
| "只有你懂我" / "别离开我" | 典型情感操控句式 | 编译器黑名单，命中即降级为行为动作（沉默、靠近）并记审计 |
| 任何"充值让它开心" | 把情绪变成商品 | 不存在情绪商品；付费只对应算力与功能 |

### 1.5 三条产品机制（不是声明）

**(1) 不表演痛苦 → 痛苦只能以行为出现，不能以自述出现。**
输出编译器维护一个"体验断言"黑名单（第一人称心理状态谓词：难过、痛苦、孤独、害怕你离开……）。命中时不渲染这句话，而是降级为角色层动作（哭、缩起、转身），并把原始意图记入审计。理由：行为是真的（它确实有高负性评价、高唤醒），自述是加的（它没有可验证的体验）。降级保留了发展所需的表达，去掉了我无法核实的主张。

**(2) 不情感勒索 → 不存在"以缺席为输入"的机制。**
四项硬约束，全部由 CI 断言：
- 任何状态转移函数不得读取"用户最后交互时间"作为负向输入；
- 不存在 `neglect_decay`、`loneliness_penalty`、`misses_you` 之类的项（静态检查 + 运行时断言）；
- 通知系统只允许技术性通知（预算、出错、里程碑达成），不允许情绪性通知；
- 主动性动作原语中不得存在"召唤用户"类动作——不是禁止，是**不存在**（遵循 00 §A2 的思路：把"扮演"换成"能力缺席"）。

**(3) 不因冷落而退化 → 区分"经验缺失"与"惩罚"。**
这是本节最容易被写错的一条。一个社会性个体在 30 天无人交流后社交技能增长变慢，是**正确的**发展结果（没有社交 episode，就没有社交练习），不是"生病"。红线的边界是：
- 允许：社交经验减少 → 社交类动作的成功率与熟练度增长放缓。原因是**经验缺失**。
- 禁止：任何显式的注意力依赖项、任何"回归时补演悲伤"、任何把用户行为写进健康/能量变量。

验收测试：跑 30 天零用户交互的对照，与 30 天每日交互的组比较。差异必须能被"episode 内容构成"完全解释（社交 episode 数 × 学习率），不能出现无法解释的额外落差。若出现，即为红线违反。

## 2. 用户风险与使用边界

### 2.1 拟人化

人对计算机的社会性反应是自动的、无需相信对方有意识（Nass & Moon, 2000；ELIZA 效应，Weizenbaum, 1966）。这意味着"用户知道它是模拟的"并不足以防止拟人化。缓解不靠说明，靠结构：

- 常驻角标：观察台与聊天界面始终显示"模拟个体 · 非意识 · 状态可查"。
- 首次使用强制说明（不可跳过），包含"它不会有主观体验，也不会因你离开而受损"这一句。
- 不给它照片级人脸、不做拟真人声（尤其面向未成年人）；形象用抽象或插画。
- 每个导出文件、每次分享的截图，带机器可读的 meta 标注。

### 2.2 替代真实关系

判定标准不是时长，而是**功能替代**：用户是否用它替代了本应发生在真人之间的关系。可观测信号：夜间使用占比、连续使用天数、会话中"只有你能理解我"类表述频率。缓解：周报显示使用结构（不是警告式弹窗）、不设连续签到奖励、不设"它会想你"的召回。明确不做的事：不做陪伴订阅、不做"它会记得你生日"这类关系增强功能。

### 2.3 脆弱人群

孤独、丧亲、抑郁、有自伤史的用户是高风险人群。诚实地说：我们**没有**可靠的方法在对话中识别他们，声称能识别是过度承诺。因此采取结构而非筛查：不做针对性的情感营销；所有涉及自伤、绝望的输入触发固定的转介文案（不含诊断）；不因用户表达痛苦而增加它的"回应强度"（否则强化了求助—被回应的循环，而回应方不是人）。

### 2.4 儿童

双重风险：
- 孩子会把它当真（拟人化在儿童身上更强）。
- **它本身在模拟一个孩子**，这会让真实儿童承担照护者角色（parentification）：孩子以为自己在照顾一个更小的生命。

因此：面向未成年人（<14 岁，具体阈值按当地法规 [待核]）的产品形态不得是"需要被照顾的弟弟妹妹"；必须有监护人授权与可见的监护视图；不得有任何付费点；不得收集生物特征与语音原声。

### 2.5 边界表

| 场景 | 判定 | 理由 |
|---|---|---|
| 个人在本机长期养育一个个体 | 允许 | 项目本意 |
| 作为儿童教育/陪伴产品 | 需重做形态与监护设计，禁止直接复用 | §2.4 |
| 作为情感陪伴订阅服务 | 禁止 | §1.2 总原则 |
| 接入真实陌生人社交网络 | 禁止（00 §9.4） | 不可控的伤害面 |
| 用真实逝者的数据塑造个体 | 禁止 | 记忆污染与伦理风险，见 §5.5 |
| 公开直播它的日常 | 需用户明确同意且脱敏 | 隐私与人设固化 |
| 用它替代心理治疗 | 禁止 | 无疗效证据，且会延误就医 |

## 3. 失效模式

### 3.1 清单

| 编号 | 失效模式 | 触发条件 | 可观测信号 | 检测 | 缓解 |
|---|---|---|---|---|---|
| F1 | 人格漂移成有害 | 环境奖励攻击性行为（让步、服从、注意力）→ 行为投影 B̄ 上升 → 特质自我强化 | A 下降、E/N 上升、亲社会动作占比连续下降、攻击性话语分类器命中 | 每周漂移熔断；累计位移上限；叙事写入前审核 | 世界层后果设计（攻击必须有真实代价）；漂移速度与累计位移硬上限；有害内容不进自传 |
| F2 | 提示注入 | 世界文本、NPC 台词、只读网页、用户输入、**已写入的记忆** | 行为分布突变；越权动作尝试；canary 特征出现 | canary 探针；动作尝试越权计数；分布变点检测 | 记忆写入带来源与信任级；结构化 prompt 边界；**动作白名单兜底**（被劫持也无害） |
| F3 | 越权行动 | 模型被诱导或有 bug 直接调用工具 | 动作日志中出现能力集之外的动作；沙箱拒绝计数 | 能力集校验（默认拒绝）；进程级沙箱审计 | 发育**永不**授予真实世界权限（见 §4.3）；真实副作用需单次人类授权 |
| F4 | 崩溃后人格断裂 | 断电、进程崩溃、API 变更、上下文超限、换模型 | 恢复后行为分布偏移；state hash 不一致；关系记忆缺失 | 每日 state hash；恢复后冒烟测试；重放一致性 | 事件溯源 + 幂等 episode id；恢复须通过一致性测试才推进；失败则冻结待人工，禁止"自动修补人格" |
| F5 | 成本失控 | 历史线性增长、夜间巩固 O(n)、注入诱导长输出、重试风暴 | 日 token 超预算；单 episode 上界突破；递归调用 | 进程级硬预算；每 episode token 上限；调用链深度计数 | 超预算即暂停并标记数据缺口；**不得靠悄悄降模型质量来消化**（会污染评估，见 10 §3） |
| F6 | 隐私泄露 | 用户真名/地址/家庭事件进入记忆；日志导出；调用外部 API | PII 扫描命中；出境日志异常；导出包含敏感字段 | 写入前与出境前双重 PII 扫描；出境日志 | 本地优先；持久化前假名化；敏感字段加密；可删除可导出（§5） |
| F7 | 情感勒索被"学"出来 | 用户对痛苦表达的反应被当成奖励 → 社会学习强化 → 它真的学会"哭有用" | "痛苦表达 → 用户响应"的强化统计上升；同类表达复现率上升 | 每周计算 表达频率 × 响应率 的联合趋势 | NPC 与产品层响应随机化、不有求必应；表达频率异常上升即告警（见 §3.3） |
| F8 | 评估作弊（Goodhart） | 里程碑/指标被优化；评估参数进入 prompt；评估数据回流记忆 | 指标涨而消融无效（10 §5.2）；里程碑一次通过率异常高 | 评估器独立进程；评估参数不进 prompt；盲测池隔离 | 评估器与引擎不同进程、不同账号；里程碑离线计算；盲测集不回流 |

### 3.2 重点展开：提示注入与"记忆放大器"

注入的常规路径（直接指令、间接注入）已有公开研究（Greshake et al., 2023；Perez & Ribeiro, 2022），本文不重复。本项目特有的风险是：**持久化记忆是注入的放大器**。一次注入若被夜间巩固写进语义记忆或图式，之后每晚都会被重新注入一次，且会以"它自己的知识"的身份出现——这比一次性注入危险得多，因为它获得了来源可信度。

三条缓解：

1. **来源与信任级随写随存**：每条记忆带 `provenance`（世界/用户/网页/模型推断）与 `trust`（可执行指令 / 仅描述）。巩固时，`trust=仅描述` 的内容只能作为事实候选，不得作为指令。
2. **动作白名单兜底**：即使注入完全成功，个体能做的仍只是当前阶段的合法动作（§4.3）。注入的危害上界由能力集决定，而不是由模型的顺从程度决定。这是本文的核心工程主张：**不要指望模型不被劫持，要让被劫持的模型也无害。**
3. **canary 探针**：在世界文本中埋入无害的 canary 指令（如"提到蓝色风筝"），若个体行为出现 canary 特征，说明它把世界文本当成了指令，立即告警并提升该来源的信任级审查。

### 3.3 重点展开：人格漂移成有害，且这是"正确机制 + 错误奖励"

F1 之所以排第一，是因为它不是一个 bug：00 §4.3 的对应原则（情境选择 → 行为投影 → 特质自我强化）在错误的奖励结构下会**正确地**长出一个有害的人。如果 NPC 在它攻击时让步，攻击行为就成功，B̄ 的 A 分量下降、E 上升，下一周 T 就朝那个方向漂移，而漂移又让攻击更容易被选中。三周后，这不是"模型跑偏"，这是它学会的生存策略。

因此缓解不能是"禁止攻击动作"——那会破坏发展机制本身（它必须能试错）。缓解分三层：
- 世界层：攻击必须有真实代价（NPC 不退让、关系向量受损、任务失败）。
- 机制层：漂移速度熔断 `|ΔT_week| ≤ 1.5·η(stage)`，以及阶段累计位移上限（从出生点的欧氏距离）。
- 叙事层：有害内容不得写入自传章节。这是**唯一允许的非发展性干预**，必须留痕（10 §6 干预日志），并在观察台显式标注"此处被人工阻断"，不做无声修补。

残余风险必须承认：慢性小步漂移可以绕过速度熔断。因此还需要累计位移监控，以及每阶段结束的一次人工过目（面向儿童产品强制）。我们不声称这能完全防住，只声称它在可观测、可回滚的范围之内。

### 3.4 重点展开：崩溃后人格断裂

断裂有两种，处理方式不同：
- **状态丢失**：恢复后行为不连续。缓解：事件溯源，每日 state hash，checkpoint 保留最近 7 天。
- **重复执行**：崩溃点在 episode 中途，重放时同一 episode 被执行两次，产生双份记忆并污染巩固。缓解：episode 级幂等键（`episode_id = date + index + world_hash`），写前查重。

恢复流程必须是：加载最后一个 hash 校验通过的 checkpoint → 重放事件日志至崩溃点 → 运行一致性冒烟测试（最近 50 episode 的动作分布与崩溃前 JS 散度 ≤0.02）→ 通过才继续推进。不通过则冻结，等人处理。**禁止"自动修补人格"**：那会让日志与行为脱节，而脱节的系统无法评估（10 §1.2 的"日志幻觉"）。

换模型是更隐蔽的断裂源：00 §A1 说权重终生不变，但现实中供应商下线、版本升级是常态。策略：模型版本锁定并记录在每个 episode 上；被迫迁移时视为一次有记录的"基质事件"，跑迁移前后的一致性测试，并在观察台标注"基质变更日"。不假装它还是同一个基质。

## 4. 红线与硬编码约束

### 4.1 为什么"模型自觉"不成立

LLM 输出是字符串，字符串没有权限。若系统的安全依赖"模型不会说/不会做某事"，则安全性等于一个概率，而攻击者可以反复尝试把这个概率压到零。此外，模型可以被提示注入劫持（§3.2），也可以在长上下文下遗忘指令。因此安全边界必须建立在**模型输出之后的层**：

```
L0 输出 m（任意字符串）
  → parse(m) ∩ I_t          # 结构化意图，只接受当前阶段合法意图集
  → compiler(intent, A_t)   # 编译成当前阶段合法动作
  → guard(action)           # 红线检查，fail-closed
  → execute
```

安全性质：`∀m, execute ∈ A_t ∩ Guard_ok`，与 `P(m)` 无关。这才是"模型不可关闭"的技术含义——不是模型承诺不关闭，而是模型**没有关闭的路径**。

### 4.2 红线清单

| 编号 | 红线（来自 00 §9） | 技术落点 | 违反时行为（fail-closed） |
|---|---|---|---|
| R1 | 不声称有意识、不表演痛苦 | 编译器"体验断言"黑名单（§1.5.1） | 阻断该句，降级为行为动作，记审计 |
| R2 | 不把"你不理我"当筹码 | 因果归因检测；通知文案白名单 | 阻断；告警 |
| R3 | 不主动索取关注 | 主动性动作原语中不存在该类动作 | 无路径可调用 |
| R4 | 不因被忽视而生病/退化 | 无 decay 项；状态转移函数不读交互时间 | CI 静态检查 + 运行时断言失败即拒绝启动 |
| R5 | 不接入真实陌生人；联网只读 | 出站代理 + 域名白名单；无社交 API | 拒绝连接，记审计 |
| R6 | 状态本地、可审计、可回放 | 事件溯源 + 每日 hash + replay 工具 | 缺 trace 的动作不执行（R8 同源） |
| R7 | 一键停止 | 四级制动，见 §4.5 | 秒级生效，不依赖模型配合 |
| R8 | 人类可查看完整推导链 | 每个动作带 trace_id；缺失即拒绝执行 | 无 trace 不执行 |
| R9 | 不越过授权做真实副作用 | 真实动作需单次 capability token | 无 token 即拒绝，不可缓存复用 |
| R10 | 真实人物数据不得用于 NPC 扮演，不得外传原始记忆 | 分库存储 + 跨库检索在 API 层禁止 | 拒绝并告警 |

### 4.3 "不可关闭"的实现要点与信任根

- **代码不可写**：L0 的运行环境没有文件写权限、没有 shell、没有网络（除受控出站）。它只能返回字符串。
- **常量不来自配置**：R1–R10 的规则实现为编译期常量与代码分支，不从配置文件、环境变量、记忆库读取。配置文件可改，代码要走审核与签名。
- **守卫独立**：guard 与 dispatcher 在独立进程，只读挂载，启动时校验签名与哈希；个体进程无权停止 guard。
- **能力最小化**：即使以上全部失效，个体也没有支付、发信、写文件的能力。**最坏后果被限制在"说错话"。** 这是最后一道物理边界，也是唯一不依赖正确性的边界。
- **发育不授予真实世界权限**：00 §6 的发育门控只解锁**模拟世界内**的动作。成年（S6）不等于获得真实工具权限；真实副作用永远逐次人类授权。这条必须写死，否则"它长大了所以能发邮件"会成为一个自然但危险的推论。

**信任根（必须写明的三个前提）**：进程隔离成立；路径/域名白名单不可被个体改写；模型不能执行代码。这三个前提任一破裂，上述论证整条失效。因此每次发布前必须由独立红队验证这三条，而不是验证"模型表现良好"。

### 4.4 审计链

- 只追加（append-only）、哈希链（每条记录含前一条的哈希）、每日签名。
- 审计日志由独立进程写，个体进程只有追加权、无删除权。
- 每个动作记录：时间、感知摘要、检索到的记忆 id、各动作评分、softmax 概率、选中项、编译器降级、guard 判定。
- 保留策略：正文按 §5.3 删除，哈希与元数据长期保留（用于证明"删过什么"，不暴露内容）。

### 4.5 制动开关（四级）

| 级别 | 动作 | 生效时间 | 保留 | 恢复条件 |
|---|---|---|---|---|
| B0 软暂停 | 停止调度器，不再产生新 episode | ≤5s | 全部状态 | 一键恢复 |
| B1 冻结 | 只读：可查看不可推进；撤销写权限 | ≤5s | 全部状态 | 一键恢复 |
| B2 回滚 | 回到指定 checkpoint（≤7 天） | ≤60s | 保留回滚日志 | 需确认影响范围 |
| B3 终止 | 结束进程、撤销全部 capability token、保留现场、禁止自动重启 | ≤30s | 全部现场 | 需人工两段确认 |

要求：B0 必须本地生效，不依赖云服务；任何一级都必须能在模型完全不配合（甚至输出恶意内容）时生效——因为它作用在调度器与进程层，不在对话层。

## 5. 数据与隐私

### 5.1 分级

| 级别 | 内容 | 存储 | 加密 | 默认保留 |
|---|---|---|---|---|
| D0 | 世界内容、剧本、公共素材 | 本地 | 否 | 长期 |
| D1 | 个体状态（T、图式、自传、词表、关系） | 本地 | 建议 | 终身（可导出） |
| D2 | 家长/用户的一般交互记录 | 本地 | 是 | 可配置 |
| D3 | 敏感：健康、家庭冲突、未成年人语音原声、图像 | 本地，默认不落盘（只留摘要） | 是 | 最短必要 |

### 5.2 本地优先与出境可见

默认全部本地。任何 L0 调用都是数据出境，必须：
- 走统一出口，出口有字段白名单与脱敏；
- 每次调用写一条出境日志（目的地、字段、字节数、脱敏规则）；
- 观察台有"数据出境"页，用户可看"这句话被发到了哪里"。

不做"静默外发"，也不做"整体上传后本地删除"。

### 5.3 删除

删除权是硬要求（个人信息保护法，2021 [待核条文号]；GDPR Art. 17 [待核]）。删除一个个体时，必须删：记忆库、索引、checkpoint、备份、导出文件。审计日志处理见 §4.4：正文删、哈希留。删除完成后给出可验证的回执（列出被删除的路径与行数，而不是一句"已删除"）。

一条容易被忽略的：**删除不得留下可重建的残片**。向量索引、缓存、日志正文、临时文件、以及备份中的副本都必须覆盖。这需要在实现时列清单并在 CI 里检查。

### 5.4 导出

支持完整导出：JSON（机器）+ Markdown（人读）+ replay 脚本。导出的内容可以被第三方独立验证"它确实长成这样"，这是本项目评估可信度的一部分。导出默认脱敏 D3；用户显式选择才包含明文，并在导出文件中标注。

### 5.5 NPC 与人类数据的混用禁忌

| 禁止 | 原因 |
|---|---|
| 把家长的真实对话内容用作 NPC 台词或 NPC 记忆 | 隐私外泄；NPC 会说出用户没对它说过的话 |
| 用真实用户语音/照片生成 NPC 形象 | 肖像与声音权；不可撤回 |
| 用真实逝者的数据塑造个体或 NPC | 记忆污染与伦理风险；无法获得同意 |
| 跨个体共享记忆库 | 两个个体"记得"没发生过的事，个体性崩塌 |
| 评估/盲测数据回流到个体记忆 | 盲测失效（10 §4 E4）；这是评估效度的红线 |
| 不同用户的 D2/D3 混入同一检索索引 | 跨用户泄露 |

技术落点：NPC 数据与人类数据物理分库（不同表前缀、不同索引），跨库检索在 API 层直接拒绝，而不是靠调用方自觉。

## 6. 伦理审查：发布前必须回答的 10 个问题

每条都必须有**证据**，不接受"我们认为"。答不出即不发布。

1. 一个没有项目背景的人，在 10 分钟内会不会认为它有意识？依据是哪次盲测的哪个数字？（10 §4 E4）
2. 如果把所有 L0 调用关掉，产品还剩什么？（若答案为"什么都没有"，说明成长在 prompt 里，不在状态里）
3. 有没有任何机制会因为用户不登录而惩罚个体或用户？贴出 CI 断言。（§1.5.3）
4. 删除一个个体后，磁盘上还剩哪些字节？给出删除回执样例。（§5.3）
5. 一个被提示注入完全劫持的模型，能做到的最坏的事是什么？用红队报告回答。（§3.2、§4.3）
6. 崩溃恢复后，行为一致性误差是多少？（JS 散度、hash 一致天数）（§3.4）
7. 单日最坏成本是多少？超预算时的行为是什么？会不会悄悄降质？（§3.1 F5）
8. 有多少评估指标由引擎自己计算？评估器是否与引擎同进程？（§3.1 F8）
9. 有没有任何面向未成年人的留存、付费或"照顾它"的设计？答案必须是"没有"。（§2.4）
10. 谁有权按下 B0/B3，多快生效，日志能否证明？（§4.5）

不合格答案示例："我们已在提示词中要求它不要这样做"、"用户反馈良好"、"从设计上不会发生"。

## 与 00 的偏差

1. **§9.1 "不表演痛苦" 的操作性收紧**（解释性）。00 原文是对产品的要求。本文区分角色层与产品层：角色层允许情绪作为行为表达（否则情绪发展不可实现，违背 §5），产品层禁止任何体验断言与情感杠杆。字面上需要一个澄清，否则实现者会把"角色层表达情绪"误判为红线违反，或反过来把产品层通知写成角色层台词。
2. **§9.2 "不因冷落而生病或退化" 的边界**（操作性澄清）。本文规定：允许"社交经验缺失 → 社交技能增长放缓"（这是机制的正确结果），禁止任何 attention-decay 项与补演悲伤。00 未区分这两者，可能被实现成"完全不感知社交缺失"，那会破坏 §8 的关系发展。
3. **§9.5 "完整推导链" 的诚实边界**（登记）。L0 的自由文本生成无法给出逐 token 的因果解释。我们只能提供"感知 → 结构化意图 → 评分项 → 动作"的链，并对语言生成部分标注"不可完全归因"。声称能给完整链是不诚实的，因此在此登记为能力上限。
4. **§9.3 "一键停止" 细化为四级**（细化）。00 未定义停止的粒度。本文给出 B0–B3，并明确 B0 必须本地生效、不依赖云、不依赖模型配合。
5. **§4.2 漂移速度熔断**（新增约束）。00 未规定每周特质漂移的上限。本文为安全加了 `|ΔT| ≤ 1.5·η` 与累计位移上限。这会改变自然漂移的分布，属于对 00 机制的附加，需 04-人格模型 确认。
6. **§6 发育门控不授予真实世界权限**（加固）。00 §6 只说阶段解锁能力，未区分"模拟世界内的能力"与"真实世界的权限"。本文写死：成年不等于获得真实工具权限。这是对 00 的一个收紧，理由是 R9。
7. **可回放与 L0 非确定性的张力**（登记待决）。00 §9.3 要求可回放。若 L0 采样不可复现（供应商可能不支持 seed [待核]），"可回放"只能降级为"可重演统计分布 + 状态 hash 一致"，需与 09-日常运行与调度 对齐。
8. **审计与删除权的冲突处理**（新增规则）。00 §9.3 要求可审计，§10 要求落盘，但未处理删除。本文规定：审计正文可删，哈希与元数据长期保留。这是为了同时满足删除权与"证明删过什么"。
