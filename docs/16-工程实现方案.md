# 16 工程实现方案

> 一句话：把蓝图压成一条能在这台机器上跑起来、没 API key 也能跑、跑完能证明自己没作弊的最小工程路径。

本文是 [02 系统架构](./02-系统架构.md) 与 [12 路线图](./12-路线图与成本.md) 的施工图：给出仓库结构、技术选型、关键代码形状、测试与部署，以及 M0 的七个可验收里程碑。它不改变任何设计决策，只回答"怎么落"。

---

## 0. 结论先行

| 维度 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.10（本机 `D:\miniforge3\python.exe`） | 已在机器上；数据/文本密集型；无需编译链 |
| 第三方依赖 | **尽量为零**（stdlib：`sqlite3`/`json`/`asyncio`/`urllib`/`unittest`） | 网络不确定，少一个依赖少一类长跑故障；可选 extras 见 §2 |
| 进程模型 | 单进程 asyncio 常驻 + Windows 计划任务拉起 + 看门狗 | 见 09；不做多进程，避免状态竞态 |
| 存储 | SQLite（真相）+ 追加式 JSONL（事件）+ Markdown（人读投影） | 见 05；不引向量库，检索用 FTS5 + 余弦（numpy 可选） |
| LLM | OpenAI 兼容 HTTP，`Provider` 抽象；**必须有 Mock 与 Cassette 两种离线实现** | 没 key 也要能开发、能回归、能跑 30 天 |
| 前端 | 只读静态页 + 极简 `http.server` JSON API | 观察台是审计工具，不需要前端框架 |
| 测试 | `unittest` + 回放夹具 + 不变量性质测试 | CI 不依赖网络与真 LLM |

一句话：**先把"能重放、能离线、能证伪"的骨架搭出来，再谈智能。**

## 2. 技术选型细节

| 项 | 选 | 备选与不选的理由 |
|---|---|---|
| JSON | `orjson`（可选）→ 缺失则 `json` | 少量性能收益，不是关键路径 |
| HTTP | `urllib.request` | 避免 `httpx` 版本问题；LLM 调用是低频 |
| YAML | `PyYAML`（必需） | 配置可读性 > 少一个依赖 |
| 数组 | `numpy`（可选） | 余弦与 softmax 手写即可；装上更快 |
| Web | `http.server` + 静态 HTML | 观察台只读，不需要框架 |
| 测试 | `unittest`（避免 pytest 依赖） | CI 零依赖 |
| 格式化 | `ruff`（可选，开发期） | 不阻塞 |

`pyproject.toml` 声明 `requires-python = ">=3.10"`，`dependencies = ["PyYAML"]`，extras：`dev = ["ruff","mypy"]`。

## 3. 核心类型（`types.py`）

字段与 [13 数据契约](./13-数据契约.md) 一致，这里只给形状：

```python
@dataclass(slots=True)
class Perception:
    t: datetime
    channel: str                 # 触觉/视觉/听觉/…
    fields: dict[str, Any]       # 已按阶段裁剪
    salience: float

@dataclass(slots=True)
class Appraisal:
    novelty: float; threat: float; control: float
    valence: float; arousal: float
    pe: float                    # 预测误差
    schema_hit: bool

@dataclass(slots=True)
class Episode:
    id: str; day: int; slot: int
    world: dict; perception: dict; appraisal: dict
    candidates: list[dict]       # 全部候选动作与分数（审计用）
    action: dict                 # {id, intent, source}
    language: dict | None        # {intent_slots, tokens, syntax_level}
    outcome: dict; salience: float
    catch_up: bool; synthetic: bool
    tokens: dict                 # {in, out, cost}
```

**不变量在类型层就能挡一部分**：`Episode.candidates` 必填（I 审计），`language.syntax_level` 由编译器写，不接受外部传入。

## 4. 运行时主循环（`runtime/runner.py`）

```python
async def run_day(day: int, ctx: Ctx) -> DayReport:
    plan = generate_day_plan(ctx.rng, stage=ctx.stage, day=day)
    for slot in plan.slots:
        await ctx.clock.sleep_until(slot.at)
        ep = await run_episode(slot, ctx)
        ctx.store.append_episode(ep)          # 事务：事件 + 行 + 哈希链
    if plan.night:
        await consolidate(day, ctx)           # 六步，幂等
    if day % 7 == 0:
        settle_traits(day, ctx)               # B̄ 投影 + 漂移
    judge_stage(day, ctx)                     # 里程碑 + 停留期
    return DayReport(...)

async def run_episode(slot, ctx) -> Episode:
    obs    = ctx.world.observe(slot)
    perc   = ctx.perception.project(obs, ctx.stage, ctx.body)
    appr   = ctx.appraisal.evaluate(perc, ctx.traits, ctx.drives)
    mem    = ctx.memory.retrieve(perc, appr, budget=ctx.budget.retrieve)
    acts   = ctx.body.enumerate_actions(perc, appr, ctx.stage)   # 只含已解锁
    prior  = await ctx.llm.prior(perc, appr, mem, acts)          # 调用 #1
    scores = ctx.policy.score(acts, perc, appr, ctx.state)
    chosen = ctx.policy.select(scores, prior, ctx.rng)
    lang   = ctx.language.compile(chosen, ctx)                   # 无 LLM
    safe   = ctx.safety.check(lang, chosen, ctx)                 # 出口拦截
    ok     = ctx.world.apply(safe, ctx)
    return Episode(...)
```

三条硬约束写在代码形状里：

1. **`acts` 先于 LLM**：候选集由引擎枚举，LLM 只能在已解锁集合里挑（I1）。婴儿的 `acts` 里没有"说完整句子"。
2. **`lang` 在 LLM 之后、在落地之前**：语言由编译器生成，LLM 只提供语义槽（I5）。
3. **`candidates` 全量落盘**：没有候选与分数就没有审计，等于没有 `/why`。

## 5. LLM 接入层：可离线、可回放、可限支

### 5.1 抽象

```python
class Provider(Protocol):
    async def complete(self, req: LLMRequest) -> LLMResponse: ...

@dataclass
class LLMRequest:
    system: str; user: str
    schema: dict | None          # JSON Schema，None 表示自由文本（仅巩固用）
    max_tokens: int; temperature: float
    cache_key: str               # 由内容和版本算 sha256
```

三个实现：

| 实现 | 用途 | 关键点 |
|---|---|---|
| `OpenAIChat` | 生产 | 超时 30s、重试 2 次（指数退避）、429/5xx 分类处理 |
| `MockProvider` | 开发/CI | 由 `hash(prompt)` 确定性地产出一个**合法**结构化响应；行为可预测但不重复 |
| `Cassette` | 回放 | 按 `cache_key` 录/放 JSONL；回放缺失直接失败（不静默） |

**为什么 Mock 必须是确定性的**：否则测试无法断言"同种子同结果"，30 天冒烟也就失去意义。

### 5.2 结构化输出

```
complete(schema) → validate → 失败则一次修复重试（附错误信息）→ 再失败用确定性兜底
```

兜底 = 取 `policy` 打分最高、且语义槽最简的动作。**兜底必须留痕** `action.source = "fallback"`，并在指标里成曲线；兜底率上升通常意味着 prompt 或 schema 出问题了。

### 5.3 成本与硬闸

- 每 episode 记 `tokens.in/out` 与单价，写 `llm_calls` 表；
- 日预算 `budget.daily_cny`，到 80% 降级（关掉巩固里的 LLM 步）、到 100% 硬停并落 `budget_exceeded` 事件；
- prompt 前缀稳定（system + 静态 schema 在前），为缓存命中留条件。

### 5.4 Prompt 纪律（可测）

`prompts.py` 全为纯函数，`tests/golden/` 存快照。三条 CI 规则：

1. 渲染出的 prompt 里**不得**出现特质形容词（"内向/好奇/敏感"）——用词表扫描；
2. 不得出现"你是……"式人格设定；
3. 同一状态必须渲染出同一字符串（排序、格式化、无时间戳）。

## 6. 各子系统实现要点

| 模块 | 职责 | 关键函数 | 验收 |
|---|---|---|---|
| `body/perception` | 按阶段裁剪通道与字段 | `project(obs, stage) -> Perception` | S0 无"文字"字段（测试断言键集） |
| `body/primitives` | 44 原语与解锁表 | `unlocked(stage) -> set[str]` | 越界测试：S0 的 `speak` 不存在 |
| `body/compiler` | 语义槽 → 文本，单向降级 | `render_utterance(intent, stage)` | 超等级必降级，降级链可单测 |
| `cognition/appraisal` | 评价（纯函数） | `evaluate(perc, traits, drives)` | 同输入同输出；无随机 |
| `cognition/policy` | 打分与选择 | `score(...)` / `select(...)` | `bias_t = f(T)` 现算（I11） |
| `cognition/traits` | 周投影与漂移 | `project_week()` / `settle()` | 冻结 T 行为不变（H3） |
| `memory/retrieve` | 三路检索 + MMR | `retrieve(q, budget)` | 预算内、可复现排序 |
| `memory/consolidate` | 六步、幂等 | `run(day)` | 重跑同日不产生重复（I12 关联） |
| `stages/milestones` | 纯函数 evaluator | `registry[code](db) -> bool` | evaluator 不得 import llm（import 图测试） |
| `safety/gate` | 出口红线 | `check(lang, action) -> SafeAction` | 红样本必须拦截并留证 |
| `observe/console` | 只读投影 | `today()/profile()/why(ep)` | 无写接口；`/why` 覆盖每次选择 |

## 7. 确定性：可重放的前提

三件套缺一不可：

1. **唯一随机源**：`rng.derive(individual_id, day, slot)` → `random.Random(seed)`；全仓禁止 `random.` 直接调用（CI 用 grep 挡）。
2. **可注入时钟**：`Clock` 三态（real / scaled / mock）；逻辑里禁止 `datetime.now()`，CI 同样用 grep 挡。
3. **确定性格式化**：JSON 落盘统一 `sort_keys`、浮点统一 `%.6f`；集合遍历一律先排序。

有了这三件，"同一 seed 跑两遍得到字节级相同的事件日志"就是可测的——这也是崩溃恢复与实验复现的底座。

## 8. 测试策略

| 层 | 内容 | 频率 |
|---|---|---|
| 单元 | 每个纯函数：编译降级、打分、投影、检索排序 | 每次提交 |
| 性质 | 不变量 I1–I12、AV1–AV5：随机生成状态跑断言 | 每次提交 |
| 回放 | Cassette 录一次真 LLM，之后离线回放 | 每次提交（无网） |
| 黄金 | prompt 快照、Episode 结构快照、日报快照 | 每次提交 |
| 冒烟 | Mock 全速跑 30 天，断言零异常 + 不变量 | 每次提交（≤2 min） |
| 长跑 | 真 LLM 跑 7 天，看成本与稳定性 | 手动/周 |

边界检查也进 CI：`ast` 扫 import，`store` 之外不得出现 `sqlite3`、`llm` 之外不得出现 `urllib`、`stages/milestones` 不得 import `llm`。

## 9. 可观测性与运维

- **事件日志**：每条 episode 一个事件，前一条哈希进下一条（防篡改，呼应 09）；
- **日志分级**：`run.log`（结构化为 JSONL，不用 print）、`error.log`；
- **指标**：每日写 `metrics/day-XXX.json`（episode 数、兜底率、token、成本、不变量告警）；
- **`/why <episode_id>`**：重放该 episode 的全部输入与分项分数，输出人类可读推导链（10 §6 的审计链）；
- **崩溃恢复**：RTO ≤ 30 s；缺失的 slot 标 `catch_up`，投影权重 ≤ 0.5（I10）；
- **备份**：每日 `sqlite3 .backup` + 事件日志追加归档；保留 30 天。

## 10. 部署（Windows，本机）

```powershell
# 一次性
schtasks /Create /TN "PersonaRun" /SC ONLOGON /TR "D:\miniforge3\python.exe -m persona core --config config\persona.yaml"
# 看门狗（每 5 分钟）
schtasks /Create /TN "PersonaWatch" /SC MINUTE /MO 5 /TR "D:\miniforge3\python.exe -m persona watch"
```

- 单实例锁（`data/.lock`，带 PID 与心跳时间戳），第二次启动直接退出并打日志；
- 路径全用 `pathlib`，日志文件用 `utf-8` 显式编码（Windows 默认 GBK 会吃掉中文）；
- 断网 → 进入 `offline` 态：不补 episode、日记明示"系统离线"，不写"它睡了"（09 同口径）。

## 12. 主要工程风险

| 风险 | 触发信号 | 缓解 |
|---|---|---|
| LLM 输出不合 schema | 兜底率 > 15% | 收窄 schema、加 few-shot、降 temperature |
| 成本超支 | 日成本 > 预算 80% | 硬闸 + 巩固降级 + prompt 缓存 |
| 长跑腐化（内存/日志膨胀） | 进程 RSS 单调上升 | 每日重启一次干净进程；日志按天切 |
| Windows 编码/路径 | 中文乱码、路径不存在 | 全 `pathlib` + 显式 utf-8 + CI 冒烟 |
| 浮点不确定 | 同 seed 两次结果不同 | 固定格式化；排序先于求和 |
| 状态竞态 | 巩固与 episode 交错写 | 夜间四大锁（09）；单进程 + 事务 |
